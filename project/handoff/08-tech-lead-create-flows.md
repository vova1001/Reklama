# 08. tech-lead: минималистичное приложение, лента слева, создание заданий и анкет с проверкой

## Задача (менеджер, по словам заказчика)
1. **Раскладка как в Threads / goesti (стиль, не копия):** слева узкая вертикальная навигация иконками (лента, создать, мои, профиль, настройки, внизу аватар),
   по центру — одна колонка ленты (~600px), справа — только если есть смысл (можно убрать). Больше воздуха, меньше рамок и плашек, аккуратно.
   Мобильная — нижняя навигация.
2. **Палитра — более минималистичная, подобрать заново:** почти монохром (белый/графит, 2–3 оттенка серого) + один фирменный акцент
   (изумруд — оставить или предложить лучше, но один). Обновить `project/design/tokens.md`, применить к приложению, входу и главной. Контраст ≥ 4.5:1.
3. **Создание задания (режим «Бизнес»)** — красиво, пошагово или одной аккуратной страницей:
   - обязательные поля: название, город (или «Вся Россия»), сфера/категория, формат (Reels/Shorts/YouTube/VK Клипы/TikTok/Telegram), тип (открытое / с одобрением),
     условия (просмотры, лайки — числа), оплата за выполнение (₽), срок публикации;
   - ниже — **динамические блоки**: «Описание» (абзацы), «Что показать» / «Требования» — списки пунктов: добавить / удалить / перетащить порядок; можно добавлять новые блоки (заголовок + пункты);
   - предпросмотр карточки, как её увидят авторы;
   - после «Отправить» — статус **«На проверке»** (модерация), в «Мои задания» видны статусы: черновик / на проверке / опубликовано / отклонено (с причиной). Черновик сохраняется.
4. **Анкета автора (режим «Автор»)** — так же: обязательные (имя, город, темы, площадки со ссылками и подписчиками) + динамические блоки (о себе, форматы и цены — пункты, примеры работ — ссылки);
   после отправки — **«На проверке»**; в ленте бизнесу будут видны только одобренные (позже).
5. **Лента:** автору — опубликованные задания (сейчас могут быть пустыми — красивое пустое состояние, без выдуманных данных); бизнесу — свои задания и подсказка «Создать».
6. **Админку не делать.** Но на бэкенде: статусы модерации и переходы (draft → pending_review → published | rejected), сервисный метод модерации за интерфейсом (позже для админки), журнал смен статуса.
- Бэкенд: Go, три слоя, интерфейсы, валидация на сервере (длины, числа, количество пунктов/блоков, URL), лимиты на создание, тесты (-race), миграция; контракт OpenAPI.
- Скриншоты не нужны. e2e: создать задание с блоками → «На проверке»; анкета автора → «На проверке»; черновик. Коммит, не пушить. Отчёт по слоям сюда.

## Отчёт (техлид)
- **Сделано.** Приложение пересобрано: всё служебное — слева (знак, Лента / Создать / Мои у бизнеса или Анкета у
  автора, Профиль, Настройки, «Бизнес / Автор», внизу аватар с меню и «Выйти»); 768–1199 — колонка иконок с
  подсказками, ≥1200 — с подписями; справа — одна колонка до 600px, правой колонки и виджетов (прогресс, подсказка,
  тариф, «как это работает») нет; напоминание о профиле — одна тонкая строка, закрывается; тариф — в настройках.
  Телефон — шапка (знак, режим, аватар) и нижняя навигация. Палитра — почти монохром (белый, 3 серых, графит) +
  изумруд; все тексты ≥ 4.5:1 (`project/design/tokens.md`), применена к приложению, входу и главной.
  **Задание** — одна страница: обложка 16:9 с кадрированием, название, сфера (общая или своя), город / «Вся Россия»,
  форматы, «Любой автор / С одобрением», просмотры и лайки, оплата ₽, срок (дд.мм.гггг + «3 дня / Неделя / …»),
  блоки (Описание, Что показать, Требования + свои; пункты — Enter, перетаскивание и стрелки, удаление блока с
  «Вернуть»), до 6 фото, «Как увидят» (предпросмотр). Черновик сохраняется сам, при уходе с несохранённым —
  предупреждение; «На проверку» недоступна, пока не заполнено обязательное — причина по наведению и фокусу.
  После отправки — «На проверке»; «Мои задания» — фильтр по статусам, причина отказа, «Изменить», «Удалить»,
  «В черновик». **Анкета автора** — так же: фото 1:1, имя, город, темы (до 5, своих до 3), площадки (ссылка +
  подписчики, вид по домену), блоки (О себе, Форматы и цены, Примеры работ — ссылки), до 9 работ → «На проверке».
  **Лента:** автору — опубликованные задания («Подробнее», «Показать ещё»), пусто — «Заданий пока нет»; бизнесу —
  свои на проверке и опубликованные, «Черновики: N», «Создать». Аватар профиля — загрузка с кадрированием.
- **Бэкенд.** Статусы и переходы в домене (`draft → pending_review → published | rejected`, владелец может вернуть
  с проверки), смена — из ожидаемого статуса + журнал `moderation_log` в одной транзакции. Модерация —
  `service.Moderation` за интерфейсом `Moderator` (`Decide`, `History`; задания, анкеты, свои категории), без админки.
  Проверка на сервере: «форма» при каждом сохранении (длины, числа, перечни, ссылки https, до 8 блоков × 15 пунктов,
  6000 знаков, свои фото нужного назначения) и «полнота» при отправке, ошибки по полям (`blocks.N`, `platforms.N`).
  Лимиты: заданий на пользователя, отправок на проверку в сутки, загрузок фото (Limiter), квота фото, своих категорий.
  Свои категории: нормализация (регистр, ё, пробелы), без дублей, подсказки похожих (вхождение, опечатки), на проверке
  видны автору сразу, после одобрения — общие. Фото: multipart до 10 МБ → тип по содержимому (JPEG/PNG/WebP/HEIC;
  GIF, SVG, анимация — отказ) → лимит пикселей до декодирования → уменьшение, поворот по EXIF, обрезка → WebP
  320/800/1600 без EXIF и геометок; пул воркеров (очередь, контекст, лимит параллельности, 503 при перегрузке);
  хранилище за `BlobStore`: PostgreSQL (`MEDIA_STORE=postgres`) или S3 (R2 / Яндекс / MinIO, `STORAGE_*`) без правки
  кода; `GET /media/{id}/{size}.webp` — 128-битные id, ETag и 304, опубликованное и аватар — всем с долгим кэшем,
  остальное — только владельцу; фото уходят на проверку вместе с заданием или анкетой; сироты чистятся раз в час.
- **Проверено.** `make test` (Docker, PostgreSQL + Redis, `-race`): зелёные, покрытие service + repository +
  transport + gateway (telegram, imaging, storage) + ratelimit — 91,0%; подпись S3 сверена с эталоном AWS; `go vet`,
  gofmt; golangci-lint — новых замечаний нет. e2e Playwright (`make e2e-up`, 1440 / 768 / 375): 103 пройдено,
  2 пропущены по замыслу — раскладка слева, режим, профиль, аватар, меню, настройки, адаптив 320–1440 без прокрутки
  вбок, контраст, задание с блоками и фото → «На проверке», черновик (сохраняется сам, открывается, удаляется), анкета
  со своей темой и площадками → «На проверке», ошибки фото (тип, размер, подделка под JPEG, отмена), проверки сервера.
  `astro check` — 0 ошибок. Скриншоты не делались.
