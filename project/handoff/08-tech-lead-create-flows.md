# 08. tech-lead: минималистичное приложение, лента слева, создание заданий и анкет с проверкой

## Задача (менеджер, по словам заказчика)
1. **Раскладка как в Threads / goesti (стиль, не копия):** слева узкая вертикальная навигация иконками (лента, создать, мои, профиль, настройки, внизу аватар),
   по центру — одна колонка ленты (~600px), справа — только если есть смысл (можно убрать). Больше воздуха, меньше рамок и плашек, аккуратно.
   Мобильная — нижняя навигация.
2. **Палитра — более минималистичная, подобрать заново:** почти монохром (белый/графит, 2–3 оттенка серого) + один фирменный акцент
   (изумруд — оставить или предложить лучше, но один). Обновить `project/design/tokens.md`, применить к приложению, входу и главной. Контраст ≥ 4.5:1.
3. **Создание задания (режим «Бизнес»)** — красиво, пошагово или одной аккуратной страницей:
   - обязательные поля: название, город (или «Вся Россия»), сфера/категория, формат (Reels/Shorts/YouTube/VK Клипы/TikTok/Telegram), тип (открытое / с одобрением),
     условия (просмотры, лайки — числа), оплата за выполнение (₽), срок публикации;
   - ниже — **динамические блоки**: «Описание» (абзацы), «Что показать» / «Требования» — списки пунктов: добавить / удалить / перетащить порядок; можно добавлять новые блоки (заголовок + пункты);
   - предпросмотр карточки, как её увидят авторы;
   - после «Отправить» — статус **«На проверке»** (модерация), в «Мои задания» видны статусы: черновик / на проверке / опубликовано / отклонено (с причиной). Черновик сохраняется.
4. **Анкета автора (режим «Автор»)** — так же: обязательные (имя, город, темы, площадки со ссылками и подписчиками) + динамические блоки (о себе, форматы и цены — пункты, примеры работ — ссылки);
   после отправки — **«На проверке»**; в ленте бизнесу будут видны только одобренные (позже).
5. **Лента:** автору — опубликованные задания (сейчас могут быть пустыми — красивое пустое состояние, без выдуманных данных); бизнесу — свои задания и подсказка «Создать».
6. **Админку не делать.** Но на бэкенде: статусы модерации и переходы (draft → pending_review → published | rejected), сервисный метод модерации за интерфейсом (позже для админки), журнал смен статуса.
- Бэкенд: Go, три слоя, интерфейсы, валидация на сервере (длины, числа, количество пунктов/блоков, URL), лимиты на создание, тесты (-race), миграция; контракт OpenAPI.
- Скриншоты не нужны. e2e: создать задание с блоками → «На проверке»; анкета автора → «На проверке»; черновик. Коммит, не пушить. Отчёт по слоям сюда.
