# 11. tech-lead: формы удобнее, мультивыбор, «+Свой», просмотр фото, пинг сайта

## Задача (менеджер, по словам заказчика и сотрудника)
1. **Пинг (сайт засыпает):** расписание GitHub Actions срабатывает раз в несколько часов — не годится. Сделать самопинг в бэкенде:
   горутина под errgroup/контекстом раз в 10 мин делает GET `${KEEPALIVE_URL}/healthz` (через публичный адрес Render, чтобы запрос шёл через их прокси),
   включается переменной `KEEPALIVE_URL` (пусто — выключено), таймаут, логирование только ошибок. Добавить в render.yaml (= PUBLIC_URL). Workflow GitHub оставить как запасной.
2. **Сфера — можно выбрать несколько** (до 5), чипы с отметкой; «+ Своя» остаётся. Бэкенд/валидация/фильтры ленты — массив.
3. **Формат — добавить «+ Свой»** (как у сферы: ввод с подсказками, нормализация, лимит). Можно выбрать несколько форматов (до 3).
4. **Срок — добавить «+ Свой»:** чипы «3 дня / Неделя / 2 недели / Месяц / + Свой»; «Свой» открывает выбор даты (и времени по желанию). Поле даты отдельно не показывать, пока не выбран «Свой».
5. **Реферальную ссылку не делать.** Лайков нет (уже убраны) — проверить, что нигде не осталось.
6. **Фото портфолио (и фото задания) — просмотр на этой же странице**, как в Telegram: открытие поверх страницы, листание стрелками/свайпом/клавиатурой (←/→, Esc), счётчик «3 / 9», миниатюры снизу, плавные переходы, закрытие по фону; без новых вкладок; доступность (фокус, aria).
7. **Формы — крупнее и понятнее:** подписи 16–17px полужирным, поля 17–18px, высота 52–56px; короткая подсказка под заголовком раздела (одна строка, 15px, не серее контраста 4.5:1);
   разделы с понятными заголовками («Основное», «Условия», «Описание», «Фото»), ровные отступы, ничего мелкого. Применить к заданию, анкете автора и профилю.
- Go три слоя, тесты (-race), e2e (мультивыбор, свои формат/срок, просмотр фото). Скриншоты не нужны. Коммит, не пушить. Отчёт 3 строки + дерево по слоям в файле.
